cuora-vault-age — the local vault, and the default backend forever (per PL-001 hard constraints).

One age-x25519-encrypted JSON doc holds every env’s records; put/rm/rotate rewrite the whole file (fine at v1 scale). Decrypted payload shape (v is the format version):

{
  "v": 1,
  "envs": {
    "dev": {
      "billing/stripe": {
        "value": "…", "version": 1,
        "created_at": "…", "rotated_at": "…"
      }
    }
  }
}

The vault takes an already-resolved [x25519::Identity] — where the identity lives is the cuora-identity port’s business (keyfile via cuora-identity-file, session keyring via cuora-identity-keyring; cuora-ops resolves it). Recipients default to that identity’s public key plus any extra recipients in the vault’s config. AgeVault::open_or_init is the bootstrap path — it runs [cuora_identity::ensure] on the caller’s chosen source.
