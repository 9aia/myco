tamias_driver_cuora

Module data 

Source
Expand description

data — one cuora-ops handle per wire op.

The driver is a reader: every view/query builds an [Ops] exactly like the CLI does (--config/--env/--actor become the config/env/actor request params, then the same CUORA_CONFIG → ./cuora.toml → ~/.config/cuora/cuora.toml search cuora verbs use) and answers from vault metadata — refs, versions, timestamps, vault kinds and routes.

Secret values never leave this process. list_records decrypts records to reach their bookkeeping fields; the SecretRecord::value is dropped the moment the row is built. The secret view reads a record only to report stored + bookkeeping — it never calls Ops::get_in, so no materialization audit event fires and no value can render. There is no reveal verb: cuora get/cuora run stay the only value edges.

Degradation: a config/env/actor that fails [Ops::load], or a vault that won’t open, becomes an {"error": …} payload inside an ok:true response — hosts render the failure inline, the same contract cuora-tui used for its “vault not readable” line.
