views — the driver’s manifest: every ViewSpec plus the wiring that turns query bindings into [ViewResult] data.

Read path: all data comes from crate::data::Ctx — one cuora_ops::Ops per wire op, loaded exactly like the CLI (--config/--env/--actor → the config/env/actor request params). Nothing here proxies cuora serve: the reads are in-process through cuora-ops, and the driver never mutates — put/rm/rotate/deploy stay on the cuora verbs and the cuora serve wire.

Secrets safety (hard requirement): no view, query, or param can render a secret value. Refs carry names only; refs/ secret read SecretRecords for bookkeeping and drop value uninspected; there is deliberately no reveal op — the TUI’s audited r→r reveal has no pavo equivalent by design.
