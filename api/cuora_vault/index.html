cuora-vault — the readable-store port.

A Vault is a store of SecretRecords keyed by (env, ref-path). Every impl stores opaque ciphertext — stores never see plaintext (ADR-0001); impls are cuora-vault-age (local file, the default), cuora-vault-cf (self-hosted Cloudflare Worker + D1), and cuora-vault-cached (read-through encrypted local cache in front of any backend, P-007). The trait is sync by design — no async runtime in the binary; an HTTP-backed impl uses a blocking client.

The contract below is conformance-tested: every impl runs the cuora-testkit suite and must agree on semantics —

  • put — upsert. New ref → version = 1, created_at = now, rotated_at = None. Existing ref → value replaced, version bumps, created_at preserved, rotated_at untouched.
  • get — Ok(None) when the ref isn’t stored in that env.
  • rm — Ok(true) removed, Ok(false) it wasn’t there.
  • list — the refs stored in that env, sorted.
  • rotate — deliberate rotation: Err(NotFound) on a missing ref, else new value + version bump + rotated_at = now.
  • envs are isolated keyspaces — same ref path in dev and prod are independent records.
