cuora-deploy-cf — push secrets to a Cloudflare account Secrets Store via the CF API v4 (cuora-deploy impl).

The Secrets Store is the canonical write-only sink: values go in and can never be fetched back — Workers bind to them directly. cuora deploy pushes the plaintext value (decrypted at the ops edge): the age-ciphertext boundary covers cuora’s own vaults; an external store that must serve values to runtimes is outside it.

§API surface used

GET/POST/PATCH/DELETE under {base}/accounts/{account_id}/secrets_store/stores/{store_id}/secrets — CF envelope {success, errors, result} on every response. Upsert = GET ?search={name} → PATCH /{id} when an exact-name row exists, else POST a create body.

The API token arrives via the env var named by token_env (default CLOUDFLARE_API_TOKEN) — never inline in config. Blocking ureq, no async runtime (AGENTS.md).
