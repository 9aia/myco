Protocol fakes on top of HttpMock — in-memory reference implementations of the two remote surfaces cuora talks to:

  • vault_wire / vault_wire_v2 — the cuora-vault-cf wire protocol, the same semantics cuora-vault-cf/worker/index.js implements against D1. Stores base64 ciphertext rows only — never plaintext.
  • cf_secrets_store — the CF API v4 Secrets Store envelope ({success, errors, result}) that cuora-deploy-cf pushes to. A real Secrets Store is a plaintext sink, so this fake records what it receives (fake values only, by rule).

Functions§

cf_secrets_store
A fake CF API v4 Secrets Store. Routes under /accounts/{account}/secrets_store/stores/{store}/secrets: GET ?search= lists (name-substring), POST creates from an array body, PATCH /{id} updates, DELETE /{id} removes — all inside the {success, errors, result} envelope.
vault_wire
The cuora-vault-cf/1 wire: single bearer token, all envs — kept for the legacy-auth path; the store side is already v2-shaped (name column, keyed list items).
vault_wire_v2
The cuora-vault-cf/2 wire protocol, in memory: scoped tokens (Bearer against any entry’s secret, CuoraHmac signed requests per token_id), per-env {read, write} scope enforcement, per-env keyspace, name-blob pass-through, and server-side version/created_at/rotated_at bookkeeping (the client’s rotate is a PUT with "rotate": true, 404 on a missing key).
