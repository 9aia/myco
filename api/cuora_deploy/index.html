cuora-deploy — the write-only push port.

Deploy targets are sinks, not sources. Some stores accept a value and never give it back — Cloudflare’s account Secrets Store is the motivating case: POST/PATCH a value in and the API literally cannot return it. A Deploy therefore has push/remove and deliberately no get/list — anything readable belongs behind the [cuora_vault::Vault] port instead.

The value pushed is plaintext (decrypted at the edge by the caller): the sink is the thing Workers/CI read the secret from directly — the age-ciphertext boundary lives at cuora’s own vaults, not at external secret stores that must serve values to runtimes that can’t hold an cuora identity.

Naming: impls map (env, ref) onto their sink’s name scheme; PushReport::name reports what the value was written as.

Sync by design — no async runtime; impls use blocking HTTP.
