tamias-driver-kuda — pavo view driver for kuda.

Answers the pavo wire ops (manifest, views, view, query) as ndjson JSON-RPC over stdio via pavo-driver-kit’s serve loop — the same {"op":…} / {"ok":…,"result"|"error":…} shape every sibling serve speaks (see pavo/crates/pavo-protocol/src/wire.rs). Also answers the discovery verbs manifest and capabilities as plain argv, plus ops (the engine ops manifest) and run (engine passthrough).

Optional surfaces: features cli/mcp embed pavo-driver-kit’s surface layer — cli <op> [args] is a generated CLI over the ops manifest (watch/mcp/acp ride as streaming subcommands), mcp serves the ops as MCP tools on stdio. Both are equivalent to the standalone tamias-driver-cli/tamias-driver-mcp surface drivers, minus the PATH/discovery hop.

Repo context: views/queries are read-only — the driver never opens .kuda/index.sqlite for writing. Engine ops are the exception by design: cli.<op> wire queries re-exec the run verb in the request’s repo and let kuda::dispatch own the outcome (cli.sync mutates .kuda/). The repo resolves from the root/dir/path request param, $KUDA_DRIVER_ROOT, or by walking up from the cwd (pavo inherits the user’s cwd, so pavo view kuda:graph inside repo X reads X’s .kuda/).

Install: cargo install --path crates/kuda-driver places tamias-driver-kuda on PATH — pavo discovers it there or under <tamias-home>/drivers/.

Modules§

ops 🔒
Engine ops — cli.<op> wire queries dispatch into the kuda engine lib through this binary’s own run verb: each call re-execs tamias-driver-kuda run <argv> with the request’s repo as cwd, so kuda::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream (the engine’s emit() exits on broken pipe — one more reason ops stay out of the serve process).
queries 🔒
Query implementations — pavo query names mapped onto kuda’s surfaces: kuda-query functions over IndexStore, the committed .kuda/ cards, and drift recomputation (kuda status semantics).
repo 🔒
Repo context — resolve which kuda-indexed repo this request is about, load its config, cards, and L2 store.
views 🔒
Driver manifest + ViewNode trees — the static half of the pavo contract, built with pavo-driver-kit constructors over pavo-protocol types. Keep in sync with pavo/crates/pavo-protocol/src/{manifest,view_node,wire}.rs.
