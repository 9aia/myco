Module ops 

Source
Expand description

Engine ops — cli.<op> wire queries dispatch into the kuda engine lib through this binary’s own run verb: each call re-execs tamias-driver-kuda run <argv> with the request’s repo as cwd, so kuda::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream (the engine’s emit() exits on broken pipe — one more reason ops stay out of the serve process).

ops answers the manifest table below as JSON. Long-running surfaces (watch, mcp, acp) are deliberately not ops — they never return, so they stay out of the request/response wire. They live in the manifest’s surfaces list instead: surface drivers (tamias-driver-cli / -mcp, the pavo-driver-kit surface layer) expose them as streaming subcommands — tamias-driver-kuda cli watch ≡ kuda watch.
