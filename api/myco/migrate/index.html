myco migrate — bring legacy ledgers to the v2 schema.

Two modes, auto-detected:

  • pm/ → project/ — a pm/ dir at the repo root is the pre-worktree layout. TODO.md/BACKLOG.md bullets become T-items, ROADMAP.md becomes a plans/ file, any other *.md becomes an issue; the pm/ dir is removed and its deletion committed on the current branch.
  • legacy project/ → v2 — files already on the project branch are normalized in place: id-less items get ids, [x]/done items drop, heading-like lines become sections, frontmatter-less files in item dirs are adopted (the filename’s number is honored when free — 0001-foo.md → ADR-0001 — collisions take the next unclaimed number with a warning; synthesized frontmatter + canonical name), everything re-emitted canonically.

Either way, bullet shapes the target doc can’t express demote to plain-task text with a warning instead of failing the run — a status:deferred in TODO.md folds into the title, a self-block drops, a textless ## merges into the section before it (demote).

AdoptClaims 🔒
Filename-number claim table for frontmatter-less adoption — one per migrate run, spanning all item dirs. A frontmatter-less NNNN-slug.md is borrowing its number: adoption honors it when no real item owns it (a taken id), and a collision probes upward past numbers other unprocessed adoptees still want (pending) so 0001-a + 0001-b + 0002-c land 1, 3, 2 — never a fresh counter id.

convert_sections 🔒
Legacy sections → v2 Sections for file (TODO.md / BACKLOG.md), allocating ids as needed. Shapes the target doc’s grammar can’t express demote to plain-task text rather than failing the migration — see demote.
demote 🔒
Demote the parts of a converted item file’s grammar can’t express to plain text, instead of failing the whole migration: a status: the doc forbids folds back into the title (the - separator unknown · tokens already use), and a self-block drops — each with a warning, nothing silent. The id stands: an id’d line keeps its number, only its unemittable state demotes. src_id is the id the line carried — the item’s own number may have moved on a collision.

materialize 🔒
Turn a legacy item into a real one — keep a same-kind id or allocate from the run’s Registry. The store’s alloc_id can’t serve here: it scans all_ids, which strict-parses TODO.md/BACKLOG.md — the very files a project-mode migration is mid-way through normalizing.
migrate_ids 🔒
The id scan migrate needs mid-run — Store::all_ids strict-parses TODO.md/BACKLOG.md, which fails on exactly the legacy files a migration is there to fix. Same coverage, tolerant reads: an unparseable ledger doc falls back to the legacy parser (its kept ids still reserve their numbers), and item files reserve by filename with the same filename-vs- frontmatter cross-check MdStore does.
