myco item move — the cross-repo transfer. The item is re-created in the destination ledger’s own id sequence (kind, title, body, pri/owner/#label/epic/ms carried; blocks:/links: dropped — they name source-ledger ids), both ledgers get a provenance handoff (moved from/moved to), then the source walks to done: a file-backed item keeps its file with status done; a task’s line leaves the ledger and its handoff file drops to handoffs/archive/ — the check-prescribed home for items that are gone. Two commits, one per worktree, both under the usual --no-commit/$MYCO_NO_COMMIT rules.

There’s no distributed transaction across the two worktrees — the destination half lands first (a copy left behind beats an item deleted on both ends), and a source-side failure reports the new id so the close can be finished by hand.
