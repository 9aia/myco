pub fn new(cfg: &CfVaultConfig) -> Result<Self, VaultError>

Build a vault from resolved config values. Construction does no network I/O — the first verb does.

token_env names the env var holding the legacy bearer token; when set but empty that’s a config error, and when unset it errors only if scoped is empty too (scoped tokens can be the whole credential set). cfg.identity is the already-resolved age identity — where it lives is the cuora-identity port’s business.

Build from an already-parsed identity + a single bearer token — the test and embedding path.

Source

pub fn with_auth( url: &str, auth: BTreeMap<String, Auth>, identity: Identity, extra_recipients: &[String], private_refs: bool, ) -> Result<Self, VaultError>

Full constructor: credential map + private-refs flag. auth keys are env names; "*" is the fallback.

url must be https:// — bearer tokens and HMAC-signed ciphertext cross here, so plaintext HTTP is refused unless the host is loopback (127.0.0.0/8, ::1, localhost), the test/mock case. ./cuora.toml is the trust root: it chooses the endpoint credentials are sent to.

Source

pub fn migrate_private_refs( &self, env: &Env, ) -> Result<MigrateReport, VaultError>

cuora migrate --private-refs — re-key every plaintext-named row in env under its derived ref_key, attaching the name blob so list can still map back. The ciphertext moves verbatim — the value is never decrypted here. Already- private rows are skipped. Requires private_refs = true — the mode the rows are being rewritten to.

fn list(&self, env: &Env) -> Result<Vec<Ref>, VaultError>

Refs in env, mapped back through name blobs when private_refs is on. Fails closed on a mixed-mode vault (P-004): private mode + a row with no name blob, or plain mode + a row with one, is a VaultError, never a silently wrong listing — run cuora migrate --private-refs.
