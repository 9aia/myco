cuora-vault-cf — the Cloudflare Worker + D1 vault impl.

A Vault over HTTPS: a self-hosted Worker (source in worker/) fronts a D1 table of opaque rows — (env, key) → {ciphertext, name, version, created_at, rotated_at}. The Worker never sees plaintext. Each value is age-encrypted client-side to the configured recipients before it leaves the process; the store holds and returns base64 ciphertext only. This is the same crypto boundary as cuora-vault-age (ADR-0001) — a remote store is just a different persistence medium — but with per-secret ciphertext so rows map 1:1 to D1.

§Wire protocol (cuora-vault-cf/2)

Two auth schemes; the Worker accepts both during migration (P-003):

  • Authorization: Bearer <token> — legacy; the token travels on every request.
  • Authorization: CuoraHmac <token_id>, <ts>, <nonce>, <sig> — the token signs instead of traveling: sig = hex HMAC-SHA256(token, method+"\n"+path+"\n"+ts+"\n"+nonce+"\n"+sha256hex(body)), ts unix seconds within a ±60s replay window. The nonce makes identical requests inside one second sign differently — a legit retry isn’t a replay against the worker’s used_sig table (the pre-nonce 3-field form stays accepted during migration).

Tokens are scoped per env on the Worker side (CUORA_VAULT_TOKENS maps token_id → {env → {read, write}}); config carries cuora:// refs resolved into values before the vault is built — never inline tokens.

VerbPathBody → Response
GET/v1/{env}{"refs": [{"key": "a/b", "name": blob|null}, …]}
GET/v1/{env}/{key}{"ciphertext": "<b64>", "name": blob|null, "version": n, "created_at": rfc3339, "rotated_at": rfc3339|null}
PUT/v1/{env}/{key}{"ciphertext": "<b64>", "name": blob|null, "rotate": bool} → record metadata; rotate:true on a missing key → 404
DELETE/v1/{env}/{key}{"removed": bool}

{key} is the storage key: the bare ref path (billing/stripe) or — with private_refs (P-004) — hex HMAC-SHA256(k, env+"/"+ref) where k is derived from the age identity. Private rows carry a name blob (age ciphertext of the real ref) so list can map keys back; a store compromise then yields ciphertext and opaque hex, not which secrets exist.

Bookkeeping is server-side: the Worker bumps version, preserves created_at, and stamps rotated_at on rotate, so concurrent writers can’t race client-computed versions.

HTTP uses ureq (blocking, no async runtime) per AGENTS.md.
