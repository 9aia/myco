cuora-core — pure domain for the secrets broker: cuora:// refs, the redacting Secret newtype, the env axis (dev/staging/prod + arbitrary names), actor attribution, the op vocabulary, and the cuora.toml config model. No I/O, no ports — vaults, config sources, and the audit wire live in their own crates.

Modules§

actor
Actor ids — attribution strings like devin, human:luis, claude carried on audit events. A validated non-empty string; the human:/agent:-style prefix is allowed but not required. Attribution only — never an identity or policy boundary (CUORA_ACTOR is self-claimed and spoofable by construction).
config
The cuora.toml-shaped config model every cuora-config source loads. Six tables:
env
The env axis — dev/staging/prod plus arbitrary lowercase names. Env is resolution context (--env/CUORA_ENV/[envs]), not part of a ref’s name — and the routing axis that maps an env to a vault backend.
op
The op vocabulary — the verb names guardrails, audit events, and (later) the serve wire all share. Lowercase serde/parse forms match the CLI subcommands.
refs
cuora:// references — how code and config name a logical secret without carrying its value.
secret
The Secret newtype — a plaintext value that redacts itself.
