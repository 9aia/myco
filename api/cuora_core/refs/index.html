cuora:// references — how code and config name a logical secret without carrying its value.

cuora://billing/stripe names the secret billing/stripe; the env (dev/prod/…) is resolution context, selected by --env/CUORA_ENV/[envs] — never part of the name. The one exception is an explicit pin: when the first path segment is a known env name (cuora://prod/billing/stripe), it overrides the context for cross-env access. The ref itself stays pure — which names count as envs is decided by the caller via Ref::env_pin; config-aware resolution lives in cuora-ops.
