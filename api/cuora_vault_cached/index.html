cuora-vault-cached — a read-through, age-encrypted local cache in front of any [Vault] backend (P-007).

The cache is itself a Vault impl — a composite, not a bolt-on: get/list serve the local cache while it’s fresh (TTL), miss → remote fetch → write-through; put/rotate/rm always hit the remote first, then update or invalidate the cached row — writes never serve stale. Rows carry the remote version/ rotated_at verbatim — a cached get answers with the metadata the remote returned, not the cache’s own bookkeeping.

Freshness is TTL-bounded (CachePolicy::ttl): a cached row or listing younger than the TTL answers without a remote round-trip; past it the remote is re-fetched and the cache updated. A remote failure falls back to the stale copy — that degraded read is the offline mode the cache exists for.

Env scoping is the safety rail: CachePolicy::envs decides which envs may enter the cache at all — dev may cache aggressively while prod live-fetches (a stale prod secret is a footgun). cuora-ops builds the policy from [vaults.*] cache.

Layout: rows live in a Vault of the caller’s choice (ops wires an AgeVault at $XDG_CACHE_HOME/cuora/<vault>.age, the honest disposable-data placement); the cached value slot holds a JSON row {v, value, version, created_at, rotated_at, fetched_at} — ref paths and values stay inside the ciphertext like any vault row, so the cache needs no crypto of its own. Per-env list markers live in a small plaintext sidecar (<vault>.listed.json) — env names and timestamps only, never refs or values. Every cache interaction is best-effort: a corrupt row is a miss, a cache that won’t open degrades to remote-only pass-through, and the remote is always the source of truth.

A [Vault] that reads through a local encrypted cache to a remote source of truth. All cache access is best-effort — a cache that’s absent (None), corrupt, or fails mid-op degrades to remote-only behavior, never to a wrong answer.

Constants§

DEFAULT_TTL
Default freshness window — 300s. Long enough that a burst of cuora runs costs one remote round-trip, short enough that a rotation shows up inside a work session.
