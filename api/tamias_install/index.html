tamias-install — the one install pipeline, shared by tamias install/add/update (the CLI) and the install op of tamias serve (the JSON-RPC surface):

ref → parse → plan → fetch-cache hit or fetch+commit
    → payload manifest → bundled-driver consent gate
    → register bundled drivers → driver `install` dispatch
    → store commit

Driver work runs before the store commit: a missing or failing driver fails the install with no committed entry (the fetch-cache entry is content-addressed and stays). Bundled drivers/ are arbitrary code shipped inside the package — they are never registered or executed without explicit consent (--allow-drivers, "allow_drivers":true, or TAMIAS_ALLOW_DRIVERS=1).

Progress is reported through Progress events so each surface keeps its own rendering: the CLI prints tamias: lines to stderr and driver actions to stdout; tamias serve drops them. Consent hints embedded in errors are surface-tuned via Surface.

remove — the lightweight uninstall shared by tamias serve’s remove op and tamias ui’s Remove job: find the entry, dispatch the kind driver’s uninstall verb before dropping the store entry (a failing driver keeps it), then Store::remove. A missing driver on a non-files kind reports through warn — provider resources may remain. (files is built in; tamias uninstall / tamias-provider::uninstall is the provider-aware teardown, and the CLI’s bare remove skips dispatch entirely.)
