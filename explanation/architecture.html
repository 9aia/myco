Architecture ​

Ports-and-adapters over a flat crates/ workspace: myco-core is pure domain — item models, the id registry, the state machine — with no I/O. Ports are traits (myco-store, myco-config, myco-index); impls live in separate crates; crates/myco-cli (package myco) is the composition root that wires impls to verbs.

Design rules:

  • No unsafe, no async — the binary stays dependency-light and synchronous; no runtime to embed.
  • Git via the git CLI — myco-git shells out for the orphan branch, worktree, and per-verb commits; no libgit2/gix binding.
  • Markdown is the file spec — myco-store-md owns strict parse/emit: deterministic output, stable ordering, minimal diffs. myco-testkit freezes emit with golden fixtures and proptest round-trips, so the format can't drift silently.
  • The index is derived, never canonical — myco-index-redb snapshots ledgers into redb for status/board/org; it can be deleted and rebuilt at any time.

Boundary — work memory only ​

myco owns the ledger of intent (tasks, issues, proposals, plans, ADRs, handoffs). Neighbors own their own memory:

  • sturn — ephemeral coordination (live claims/ops/topics)
  • kuda — code memory; myco indexes work items, not code
  • peregrin — orchestration; an optional myco serve ndjson wire is deferred per adrs/0001
  • bupha — CI gate; myco check in pipelines, Item: trailers
  • mycena — surfaces TODO/FIXME in code → myco absorb
  • sepia — session lifecycle → myco handoff / myco resume

Anything needing a daemon, a multi-machine view, or arbitration between actors belongs to peregrin, not here.
